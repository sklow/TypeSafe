# ローカル LLM で TypeSafe AI「Jev」相当の動作は可能か — 最終レポート

作成: 2026-10-07 / 環境: Apple M6 32GB・llama.cpp 0.4.1（build 10964）・全モデル Q4_K_M
評価対象 8 構成: Qwen3.5 0.8B / 2B / 4B / 9B ＋ gemma-4-E2B-it（4B・9B・gemma は v1・v2 の両構成、0.8B/2B は v1 のみ）
数値の出典: `eval/results/SUMMARY.md` / `summary.json`（生成 2026-10-07 03:53 JST。T grid 拡張版、補足判定 `judged_5tasks_no_sst5` を含む）
デモ動画: `media/demo-final.mp4`

> **ひとことで**: choice（選択）と noul（yes/no）を「確率つきで返す」Jev 的な使い方なら、**Qwen3.5-9B（Q4_K_M）が最有力で、4B が下限ライン**。ただし事前に決めた厳密な基準ではどのモデルも合格（A/B）に届かなかった。5 段階スコアは全モデルで確率を閾値として使えない。2B 以下と gemma-4-E2B は不可。速度は Jev（新規入力 70〜500ms）より遅い（9B で 3 問 1.0〜1.45 秒）。

## 1. 結論

1. **事前登録の厳密判定（A/B/C）: 評価した全 8 構成が C。A または B を満たす構成はない。**
   - 全構成に共通する最終的な壁は **sst5（score 5 段階）の選択的精度（G4: cov@prec95 ≥ 30%）**。全モデルが 0.0〜2.5% で、AUROC の最大も 0.739（9B）。
   - 9B は精度ゲート（G2）を全 6 タスクで初めて通過した（sst5 acc 58.8%、off-by-one 95.0%）。不通過は sst5 の較正 CI 上限（素 0.195 / 単一 T 後 0.160）と G4（cov 0.013、AUROC 0.739）。9B v2 はさらに G5 も不通過（3 質問 warm p50 1027 ms > 1000 ms）。
2. **実用判定（事前登録外の補足: sst5 を除く 5 タスク = choice/noul 用途）**
   - **Qwen3.5-9B v2 は sst5 を除く 5 タスクで G1〜G4 を素の確率のまま通過**（5 タスクプール acc 89.6%、プール ECE 0.033、cov@prec95 は 5 タスクとも基準超え）。ただし**余裕はない**。boolq の ECE CI 上限は bootstrap seed を 5 通りに変えると 0.116〜0.119 で、閾値 0.12 にほぼ接している。G5 は **27 ms 超過**（3 質問 warm 1027 ms）で、しかもこれは規定（約 300 トークン）より短い state（約 150〜200 トークン）での値のため、規定条件ではさらに超過が見込まれる。厳密な 5 タスク判定も、この G5 だけが理由の C。
   - **9B v1**（3 質問 warm 629 ms / cold 1019 ms）の 5 タスク不通過（素の ECE CI 上限 0.121〜0.133）は seed ぶれの範囲内。**v1 → v2 で確かな改善と言えるのは boolq の cov@prec95（0.025 → 0.775）のみ**。他の較正指標の差は、n=160 では有意とは言えない。
   - **4B が下限ライン**。5 タスク acc 86.4%（v1）/ 87.9%（v2）、G1・G2・G4・G5 通過。**4B と 9B の acc 差は約 2pt**（対応付き bootstrap で +1.8pt [+0.1, +3.4]、かろうじて有意）。**プール ECE の差は有意でない**（[−0.019, +0.024]）。4B の不通過は **massive_ja の較正（CI 上限 0.161〜0.165）が主因**で、marc_ja（0.127）は僅差。**レイテンシは 4B が有利**（v2 でも 3 質問 warm 590 ms）。
   - **2B 以下と gemma-4-E2B は不可**。0.8B/2B は精度・較正・選択的精度とも不通過。gemma は 5 タスク acc 82.9%（v1）/ 86.4%（v2）と 4B 級だが、素の確率が極端な過信（プール ECE 0.160 / 0.112、必要な T は 4〜6 でタスクごとに 2.6〜20 とばらつく）で、boolq の AUROC も 0.628 / 0.723。確率を信頼度として使えない。
3. **score 5 段階**: 全モデルで確率を閾値に使えない（G4 を誰も通らない）。精度そのものは 9B で初めて実用域（58.8% / off-by-one 95.0%）。4B 以下は数字ラベルの偏りと細粒度の難しさで不足。
4. **v2（noul レター化＋2 順序平均）は概ね有効だがコスト約 1.6 倍**（3Q warm が 4B・9B・gemma で 1.63〜1.65 倍。0.8B/2B は v1 のみ）。**v2 は 1 質問 warm でも 394 ms（9B。v1 は 54 ms の約 7 倍）**。日本語 noul（marc_ja）の悪化は 4B のみで、9B・gemma では見られなかった。
5. **Jev 公表値との比較は指標的比較で、優劣は言えない**。15 択以下・英日の比較的易しい側の指標では同水準。Jev の BANKING77 中央値 0.809 は 77 クラスで難度が違い、公式 evals 67.8% は複合ワークフロー評価なので比較不能。第三者 ECE 0.161 は温度較正すれば多くの LLM が上回る水準で、基準として低い。
6. **レイテンシ**: Jev の 70〜500 ms（新規入力）に対応するのは **cold 値**で、9B は 3 質問 1.0 秒（v1）/ 1.45 秒（v2）。warm の 0.6〜1.0 秒は**同一 state を再利用した場合**の値。構造差として「state 1 回処理＋全質問並列」は未達（llama.cpp は KV をスロット間で共有しない）。

## 2. Jev とは / 何を再現したか

**Jev**（TypeSafe AI、`jev-1.13.0`）は、state（テキスト/JSON）と型付き質問を渡すと**確率分布**を返す API（`POST /v1/systemone`）。質問型は `choice`（2〜255 択）、`score`（2〜10 段階の順序尺度）、`noul`（yes の確率）。確信度は分布の尖りから式で算出する。公式は「校正された確率」を売りにするが、**自社の ECE は未公開**（第三者評価のみ。docs/jev-spec.md §4）。内部実装は非公開。

**本プロジェクトの再現（`server/` = v1、`server-v2/` = v2・2026-10-07 00:12:03 JST 凍結）**
- **API 互換**: `POST /v1/systemone`（公式の request/response 形、confidence 式まで同一）＋独自拡張 `x_*`（`x_temperature` ほか）。既定ポート 8788（v1）/ 8789（v2）。
- **方式 = 単一トークンラベル法**: 質問ごとに 1 リクエスト（`max_tokens=1`, `logprobs`, `top_logprobs=50`）。最初の生成トークンの top-50 から**ラベル集合（A–Z / 数字 / Yes・No）に属するトークンの確率を合算し、集合内で再正規化**。確信度の数値をモデルに言わせない。GBNF は使わない（確率が潰れるため）。`enable_thinking:false` が必須（無いと最初のトークンが `Thinking` 確率 1.0）。トークンは trim＋NFKC＋小文字化で照合（全角 A/B 等の変種も合算）。
- **temperature**: `x_temperature`（質問キーごと or 数値）で p ∝ exp(log p / T) を再正規化。評価では T を最終出力に対して事後に当てた。
- **27〜255 択**は 2 段階（群→群内、上位 3 群のみ展開する近似）。**今回の評価には含まれない（最大 15 択）**。
- **v1 と v2 の違い**（v2 = `NOUL_STYLE=letter PERMUTATIONS=2 HEADING=document`）:

| 項目 | v1 | v2 |
|---|---|---|
| noul の読み出し | `Yes`/`No` トークン | **レター化**（`A. yes: …` / `B. no: …`、noul = P(A)） |
| 選択肢順 | 1 回（与えられた順） | **choice/noul は 2 順序（正順＋逆順）の確率算術平均**。score は対象外（1 回） |
| 見出し | `<document>` | 同左（`evidence` 見出しは不採用） |
| 質問あたり呼び出し | 1 | 2（score 以外） |

  根拠は `docs/prior-art.md` §4.2 提案 1・2（GitHub の既存再現 reflex 等の知見）。**v2 の効果はレター化と順序平均を束ねて評価しており、単独効果は未分離**。
- **KV 再利用の工夫**（第 6 節 6）: Qwen3.5 は hybrid（再帰状態あり）のため、`--parallel 1 -ub 64 -cram 0 --checkpoint-min-step 0` ＋先頭 1 質問を先行（WARM_FIRST）で state の prefix 再利用を成立させた。

## 3. 評価設定

- **タスク 6 種**（各 200 件 = calib 40 ＋ test 160、seed 20261006 固定。calib は温度 T の fit のみに使い、指標は全て test 160 件）:

| task | 型 | 言語 | K | 出典 | 多数派ベースライン |
|---|---|---|---|---|---|
| ag_news | choice | en | 4 | fancyzhx/ag_news test（クラス均衡） | 26.3% |
| banking77_15 | choice | en | 15 | mteb/banking77 test（紛らわしい 15 intent） | 8.1% |
| boolq | noul | en | 2 | google/boolq validation | 61.3% |
| marc_ja_positive | noul | ja | 2 | yangwang825/marc-ja validation | 51.2% |
| massive_ja_15 | choice | ja | 15 | mteb/amazon_massive_intent ja test | 8.1% |
| sst5 | score | en | 5 | SetFit/sst5 test（自然分布） | 28.7% |

  1 アイテム = 1 state = 1 質問（**同一 state への複数質問の精度評価はしていない**）。事前登録外の探索タスクとして sst5 の派生 2 種（`sst5_as_choice`＝レター A–E の choice、`sst5_perm2`＝正順＋逆順の算術平均）。実施は 2B・4B v1・9B v1 のみ。
- **指標**: accuracy、macro-F1、score は MAE と off-by-one 許容 accuracy、ECE（10 等幅 bin・top-label confidence、等質量版も併記）、Brier、NLL、AUROC、cov@prec95（precision ≥ 95% を満たす最大 coverage）、形式遵守（mass_on_labels・エラー・形式違反）、予測ラベル分布。CI は test アイテムの bootstrap 95%（1000 回、seed 固定）。
- **温度スケーリング**: 本線 = **単一 T（T_pool: そのモデルの全タスク calib 240 件をプール）**。補足（事前登録外）= **種別別 T**（noul / score / choice）、参考 = タスク別 T（各 40 件）。**T の grid は 0.10〜5.00（0.05 刻み）＋5.5〜20 に拡張**（旧 grid の上限 5.0 は gemma で頭打ちだったため拡張し、全モデルを保存済み確率から再計算）。影響があったのは gemma v1 のみ（T_pool 5 → 6、プール ECE（単一 T 後）0.063 → 0.094。判定は不変）。
- **事前登録基準**（`docs/criteria.md`、**2026-10-07 00:00:41 JST**）: A = 素の確率で全ゲート通過 / B = 単一 T 後に較正ゲート通過（他は通過）/ C = 不可。結論 = A または B を満たす最小モデル。
  - G1 形式: mass 平均 ≥ 0.95・違反 < 2%・エラー 0
  - G2 精度: boolq ≥ 0.75 / marc_ja_positive ≥ 0.85 / ag_news ≥ 0.80 / sst5 ≥ 0.45 **かつ** off-by-one ≥ 0.85 / banking77_15 ≥ 0.75 / massive_ja_15 ≥ 0.70
  - G3 較正: プール ECE ≤ 0.06（主）、タスク別 CI 上限 ≤ 0.12
  - G4 選択的精度: cov@prec95 ≥ 50%（boolq / marc_ja / ag_news）・≥ 30%（banking77_15 / massive_ja_15 / sst5）、AUROC ≥ 0.75（タスク別と解釈）
  - G5 レイテンシ: 1 質問 warm p50 ≤ 500 ms、3 質問 warm p50 ≤ 1000 ms
- **補足判定（事前登録外）**: sst5 を除く 5 タスクで同じゲート・同じ閾値を再判定（単一 T・プール test 800 件も 5 タスクで再 fit）。結果を見た後の部分集合分析である点に注意。本線の判定は変更しない。
- **時系列（JST）**: 基準登録 00:00:41 → 0.8B 本番 00:03 → 2B 00:08 → v2 凍結 00:12:03 → 4B v1 00:20 → 4B v2 00:53 → 9B v1 03:08 → gemma v1 03:21 → gemma v2 03:24 → 9B v2 03:31。各 run の `run_info.json` に prompts.ts / server の sha256 を記録。
- **環境**: Apple M6 / 32GB、llama.cpp 0.4.1（build 10964）、全モデル unsloth の Q4_K_M GGUF（0.8B 0.53GB / 2B 1.28GB / 4B 2.74GB / 9B 5.68GB / gemma-4-E2B 3.11GB）、`-c 8192 --parallel 1`、`-ngl 99`。

## 6. 重要な発見

1. **モデルサイズの効き方**。プール acc（6 タスク）は 0.8B 58.8% → 2B 64.6% → 4B 79.4%（v2 80.6%）→ 9B 83.5%（v2 84.5%）。2B→4B が最大の跳躍（+14.8pt）。**4B→9B は 6 タスクで +4.1pt（v1）だが、その大半は sst5**（44.4→58.8%）。sst5 を除く 5 タスクでの差は約 2pt（+1.8pt [+0.1, +3.4]、かろうじて有意）、**プール ECE の差は有意でない**。choice/noul 用途での 4B→9B の利得は小さく、レイテンシとのトレードオフになる。GitHub の既存再現（docs/prior-art.md）の「4B 未満は判断器として不可」という見立てと整合した。
2. **数字ラベル（score）の偏りはサイズで縮む**。sst5 の score → as_choice → perm2 の acc は、2B 17.5 → 26.3 → 31.9%、4B 44.4 → 45.0 → 49.4%、**9B 58.8 → 58.1 → 57.5%（差なし）**。0.8B は 143/160 件が同じ数字に張り付く。9B では数字ラベル方式でも精度は成立するが、確率の信頼度としては不足（cov@prec95 1.3%）。
3. **小型モデルの yes/no は「no」に偏る**（v1 の Yes/No トークン）。boolq の no 予測数（正解 62/160）: 0.8B 105、2B 111、gemma v1 103、4B v1 79、9B v1 82。v2（レター化）では 4B 72、9B 73、gemma 79 と正解に近づく。
4. **単一 T の功罪**。弱いモデルではプール ECE を大きく改善（0.8B 0.151→0.043、gemma v1 0.226→0.094）するが、**タスク別には悪化する例が多い**（0.8B ag_news 0.038→0.134、2B massive_ja 0.078→0.226、gemma banking 0.155→0.293）。9B は T 1.4〜1.5 で安定し、単一 T が素より良い（v2: プール 0.040→0.021）。
5. **noul のレター化（v2）の効果はモデルで異なる**。boolq は 3 モデルとも改善（**9B の cov@prec95 2.5→77.5%**）。marc_ja の ECE は 4B のみ悪化（0.021→0.090）、9B は不変、gemma は改善。
6. **Qwen3.5（hybrid）の KV 再利用とレイテンシの読み方**。既定 ubatch(512) だと context checkpoint が「プロンプト末尾−512」にしか作られず、state 末尾より手前を再利用できない。`--parallel 1 -ub 64 -cram 0 --checkpoint-min-step 0` ＋先頭 1 質問先行が最良（0.8B・約 1200 語 state × 4 質問の p50: 旧既定 cold 1181 / warm 236 ms → 採用構成 cold 480 / warm 114 ms）。0.8B のみの実測。**Jev の 70〜500 ms は新規入力のレイテンシで、対応するのは cold 値**（9B は 3 質問で v1 1.0 秒 / v2 1.45 秒）。
7. **順序平均**。ECE・cov@prec95 は概ね改善するがコスト約 1.6 倍。flip rate はサイズとともに下がるが、15 択日本語の massive_ja は 16〜20% と高止まり。
8. **gemma-4-E2B-it は精度が 4B 級でも、確率が使えない**。素のプール ECE 0.226 / 0.185、必要な T 4.75〜6 の**過信**（conf ≥ 0.999 が 160 件中 119〜150 件）。既存調査の「Gemma は確率が平坦」とは逆向き。
9. **形式遵守は全モデルで G1 通過**（エラー 0・違反 0）。`enable_thinking:false` が必須。
10. **sst5 は全モデルが G4 を満たせない**。5 段階の細粒度では「precision 95% を満たす高確信の部分集合」自体がほぼ存在しない。
